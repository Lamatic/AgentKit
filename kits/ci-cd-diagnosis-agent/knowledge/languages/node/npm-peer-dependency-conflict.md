## Problem Overview
npm v7+ uses a strict peer dependency algorithm. When two packages require incompatible versions of the same dependency, npm throws `ERESOLVE` and refuses to install.

## Typical Error Messages
```text
npm ERR! code ERESOLVE
npm ERR! ERESOLVE unable to resolve dependency tree
npm ERR! peer react@"^17.0.0" from react-dom@17.0.2
npm ERR! node_modules/react-dom
npm ERR!   react-dom@"^17.0.0" from the root project
npm ERR! Could not resolve dependency:
npm ERR! peer react@"^18.0.0" from @testing-library/react@14.0.0
```

## Root Causes
1. **Direct Package Version Mismatch:** Your `package.json` specifies `react@17` but a dependency requires `react@18`.
2. **Stale `package-lock.json`:** The lockfile was generated by an older npm version and is incompatible with the current version.
3. **Transitive Dependency Conflict:** Two packages you depend on both require different versions of a shared third package.

## Diagnosis Steps
- Run `npm ls <conflicting-package>` locally to see the full dependency tree.
- Check the exact peer requirement mentioned in the error: `peer react@"^18"`.
- Determine if upgrading the root package resolves the conflict.

## Recommended Fixes

### Fix 1: Upgrade the conflicting package
**Description:** If the conflict is a `react` version, upgrade to the version required by the dependencies.
```bash
npm install react@18 react-dom@18
```

### Fix 2: Use `--legacy-peer-deps` (workaround only)
**Description:** Reverts to npm v6 peer dependency resolution. Use only if upgrading is not feasible.
```yaml
# In your GitHub Actions workflow
- name: Install dependencies
  run: npm ci --legacy-peer-deps
```

### Fix 3: Pin a compatible version with `overrides`
**Description:** Force npm to use a specific version of a shared dependency.
```json
// package.json
{
  "overrides": {
    "react": "^18.0.0"
  }
}
```

## Verification Steps
- Run `npm ci` locally without flags. Confirm exit code 0.
- Run `npm ls` to ensure no unmet peer dependencies remain.
